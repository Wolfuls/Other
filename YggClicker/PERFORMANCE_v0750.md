# v0.75.0 パフォーマンス検証報告

基準は v0.74.9（v0.74.8 に指定のクエスト報酬調整を適用済み）。報酬調整を維持し、戦闘・敵能力・報酬式・120秒予測・最大8時間・セーブ形式は変更していません。

## 主な原因と改善

1. UI更新時に反復するDPS・能力計算、表示中でない詳細や購入欄の更新が負荷になっていました。戦闘同期100msは維持し、定期HUDを200ms、重い欄を低頻度かつ条件変更時に更新。操作後は即時更新します。閉じた詳細画面は定期更新しません。
2. 予測条件のキーと集計を再利用し、DPSと既存収益キャッシュを各32件に制限。Lv・CP・パーク・編成・Q・報酬強化等で再計算します。ジュエルの残高依存能力が有効な場合は残高そのものもキーに含めます。HP量やAPだけの変化は、予測に影響しない範囲で除外し、生存状態等の変化は追跡します。
3. Duo Canvasは同じスプライトコマの再描画を省略し、非表示・別クエスト・切断DOMを描画対象から除外。畜産背景は元の12FPSを維持し、停止状態の同一フレームを再描画しません。DOM探索と画像生成をループ外へ移動。動作軽減設定を尊重します。攻撃タイミングと描画コマの時間軸は変更していません。
4. 初期の一括先読みを表示クエスト中心に変更し、読込済み画像を共有します。未表示クエストの素材は表示時に読み込みます。既存の表示と画像失敗時の代替処理を維持しています。
5. 復帰処理をWorkerへ移動。使用不能・起動失敗時は8ms目安の協調分割にフォールバックします。元のadvance内部をジェネレーターにし、乱数・臨時収入の次回時刻・各戦闘コンテキストを保持したままyieldします。advanceを細切れに再起動していません。
6. 復帰中は進捗モーダルで購入等を停止し、別スナップショットで計算して完了時に一度だけ反映。途中セーブと二重進行を防止。別タブが書き込み権を取得した場合は結果を破棄します。Worker失敗後は同じシード・未変更スナップショットから再計算します。

## 回帰結果

- Nodeテスト512件成功、失敗0。
- 単一・複数・高Lv・卵と鶏の4条件×10分・1時間・8時間、計12条件で旧同期 / 新同期 / 分割実行の全状態がdeepEqual。
- 32種類の乱数シードで複数部隊10分の結果が各シードごとに一致。報酬分布も一致し、近似計算はありません。
- 暴走、HP・死亡・復活、スタン、魔力、障壁、敵予約攻撃、自動休憩、複数クエスト、Q購入・切替、育成を既存・追加テストで確認。
- 小数経過時間と乱数呼出数、最大8時間、旧セーブのencode/decode一致を確認。
- 復帰中操作/保存停止、復帰ジョブ1回、別タブ書込時の破棄、Worker失敗時の同一シード再試行を追加検証。
- 実起動経路でも復帰ジョブ1回、討伐9988・因子1020100000186197が期待値と一致。復帰後に通常の自動保存へ復帰。
- PCと390px幅の実画面を確認。390px時の本文幅375pxで横はみ出しなし。
- 既存保存・手動保存・書き出しのテスト、予測キャッシュの関連変更/無関連変更、上限件数、ジュエル残高依存を確認。

## 未改善・測定上の制約

初回120秒予測は同期のまま残り、ブラウザではDPS集計の最大140msを観測しました。次の改善候補は予測自体のWorker化です。戦闘条件の多い状態ではキャッシュミスが増えます。全表示での長時間メモリ増加、モバイル実機CPU/GPUは未測定です。

file://の実画面はブラウザツールのURLポリシーにより開けず、直接確認していません。HTTP上でWorker失敗を強制した代替経路と単体テストは通過していますが、file://の実環境確認とは区別します。

再計測: node tools/performance-bench.cjs <対象ルート> <出力JSON>。旧版との照合: node tools/performance-regression.cjs <旧版ルート>。通常テスト: node --test tests/*.test.cjs。
